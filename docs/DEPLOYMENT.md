## 3. Python and PyTorch on s390x

### Why Plain PyTorch (No PyTorch Geometric)?
Standard enterprise mainframe distributions for `s390x` often lack pre-built wheels for complex C++ CUDA/graph extensions like `torch-scatter`, `torch-sparse`, or `pyg-lib`. 

PulseGuard-Z deliberately implements graph message passing using **native PyTorch sparse tensors (`torch.sparse_coo_tensor`, `torch.sparse.mm`)** and native recurrent layers (`nn.GRU`). This design choice ensures:
1. **Zero specialized dependencies:** Uses standard CPU PyTorch (`torch>=2.2.0`).
2. **Sub-15ms cold-start and evaluation:** Highly optimized on CPU IFL engines without GPU hardware.
3. **Architecture compatibility:** Directly installable from IBM Open Enterprise SDK or standard PyPI `s390x` wheels.

### Installing PyTorch on Linux on Z:
```bash
# On RHEL 9 (s390x):
sudo dnf install -y python3-pip python3-devel gcc gcc-c++
pip install --upgrade pip

# Install CPU PyTorch from standard index or IBM community wheel repository:
pip install torch --extra-index-url https://download.pytorch.org/whl/cpu
```

## 4. Production Installation & Configuration

### Step 1: Clone Repository & Create Virtual Environment
```bash
git clone https://github.com/lkishan2008-bit/-Error-404-PulseGuard-Z.git
cd -Error-404-PulseGuard-Z

python3 -m venv venv

pip install -r requirements.txt
```

### Step 2: Configure Environment Variables (`.env`)
Copy the provided template and set production secrets. Never commit `.env` to version control.
```bash
cp .env.example .env
chmod 600 .env
```

Generate a secure password hash for the dashboard operator using the included standard-library script:
```bash
python scripts/hash_password.py "YourProductionPasswordHere"
```

Configure `.env` with the generated values:
```ini
# Legacy API Key Authentication (for external ingestion services)
API_KEY=generate-a-strong-random-api-key-here
REQUIRE_API_KEY=true

# Dashboard Operator Authentication
DASHBOARD_USER=admin
DASHBOARD_PASSWORD_HASH=<salt_hex:hash_hex generated by scripts/hash_password.py>
SESSION_TTL_MINUTES=30

# CORS Allowed Origins
# Set to the exact external domain(s) accessing the dashboard:
CORS_ALLOWED_ORIGINS=https://pulseguard.your-org.com,http://127.0.0.1:8000

# Trusted Reverse Proxy IPs (for safe rate-limiting)
# Set to the IP of your local reverse proxy (e.g., 127.0.0.1 for local NGINX):
TRUSTED_PROXIES=127.0.0.1
```

## 5. Reverse Proxy Configuration (NGINX)

PulseGuard-Z should be hosted behind a reverse proxy (such as NGINX or Apache HTTP Server) to provide TLS/SSL termination, rate-limit buffering, and static compression.

### Example NGINX Server Block (`/etc/nginx/conf.d/pulseguard.conf`):
```nginx
server {
    listen 80;
    server_name pulseguard.your-org.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name pulseguard.your-org.com;

    ssl_certificate     /etc/ssl/certs/pulseguard.crt;
    ssl_certificate_key /etc/ssl/private/pulseguard.key;
    ssl_protocols       TLSv1.2 TLSv1.3;
    ssl_ciphers         HIGH:!aNULL:!MD5;

    # Security Headers
    add_header X-Frame-Options "DENY" always;
    add_header X-Content-Type-Options "nosniff" always;
    add_header Content-Security-Policy "default-src 'self' https: data: 'unsafe-inline' 'unsafe-eval';" always;

    # Forward traffic to local Uvicorn process
    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # Timeouts
        proxy_connect_timeout 60s;
        proxy_send_timeout 60s;
        proxy_read_timeout 60s;
    }
}
```

> [!IMPORTANT]
> Because NGINX sets `X-Forwarded-For`, ensure `TRUSTED_PROXIES=127.0.0.1` is declared in `.env` so PulseGuard-Z can safely read the original client IP for its 5-minute brute-force rate limiter.

## 6. Systemd Service Unit Setup

To run PulseGuard-Z as an unattended background service on RHEL / Ubuntu:

### Create Service File (`/etc/systemd/system/pulseguard.service`):
```ini
[Unit]
Description=PulseGuard-Z Fraud Detection Service on LinuxONE
After=network.target

[Service]
Type=simple
User=pulseguard
Group=pulseguard
WorkingDirectory=/opt/pulseguard/-Error-404-PulseGuard-Z
EnvironmentFile=/opt/pulseguard/-Error-404-PulseGuard-Z/.env
ExecStart=/opt/pulseguard/-Error-404-PulseGuard-Z/venv/bin/uvicorn backend.main:app --host 127.0.0.1 --port 8000 --workers 2
Restart=always
RestartSec=5
LimitNOFILE=65535

[Install]
WantedBy=multi-user.target
```

### Enable & Start Service:
```bash
sudo systemctl daemon-reload
sudo systemctl enable pulseguard
sudo systemctl start pulseguard
sudo systemctl status pulseguard
```

## 7. Verification and Operational Health Checks

Execute these checks after starting the service:

### 1. Health Status Check (Public)
```bash
curl -s http://127.0.0.1:8000/health | python3 -m json.tool
```
*Expected: `"status": "healthy"`, `"data_loaded": true`, and verified record counts (50,000 transactions, 2,000 accounts).*

### 2. Security Configuration Inspection (Public)
```bash
curl -s http://127.0.0.1:8000/auth/status | python3 -m json.tool
```
*Expected: `"auth_enabled": true`, `"mode": "enforced"`, `"query_param_supported": "disabled"`, `"trusted_proxies_configured": true`.*

### 3. Verify Protected Access Rejection
```bash
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8000/api/dashboard/summary
```
*Expected: `401`.*

### 4. Verify Operator Sign-In
```bash
curl -s -X POST http://127.0.0.1:8000/auth/login \
     -H "Content-Type: application/json" \
     -d '{"username":"admin","password":"YourProductionPasswordHere"}' | python3 -m json.tool
```
*Expected: `200 OK` with JSON object containing `"token"`, `"username"`, and `"expires_at"`.*

## 8. Security Best Practices Checklist

- [ ] **Header-Only Authentication:** Confirm `?api_key=` URL queries are rejected (verified in Step 5A).
- [ ] **No Secrets in Version Control:** Confirm `.env` is ignored via `.gitignore` (`git check-ignore -v .env`).
- [ ] **Local Interface Binding:** Ensure Uvicorn binds strictly to `127.0.0.1`, not `0.0.0.0`, routing all external traffic through the TLS-terminated reverse proxy.
- [ ] **Operator Password Salt/Hash:** Always use `scripts/hash_password.py` with 260,000 PBKDF2-HMAC-SHA256 iterations. Never store plaintext passwords.
- [ ] **CORS Restriction:** Ensure `CORS_ALLOWED_ORIGINS` specifies your organization's domain name, avoiding wildcard `*`.
- [ ] **Rate Limiting:** IP rate limiter prevents brute-force logins by blocking an IP for 5 minutes after 5 consecutive failures.
